# **ЛАБОРАТОРНА РОБОТА № 5** 

## **Тема: Навантажувальне тестування (Load & Performance Baseline) та кількісний аналіз продуктивності системи** 

#### **1. Мета роботи** 

На основі розподіленої системи з кешуванням та балансуванням (Лабораторні роботи № 1 –4) провести серію детермінованих навантажувальних досліджень та сформувати базовий профіль продуктивності (Performance Baseline). Навчитися переходити від суб’єктивних оцінок швидкодії до кількісного опису системних характеристик (Throughput, Latency Percentiles, Saturation Thresholds, Error Rates) та аналізу деградації під високим навантаженням. 

По завершенню роботи студенти повинні вміти: 

- проєктувати та реалізовувати автоматизовані скрипти навантажувального тестування (k6, Locust, Gatling); 

- формалізувати та моделювати профілі навантаження (Ramp-up, Staging, Constant Concurrency); 

- збирати та інтерпретувати фундаментальні метрики продуктивності (Throughput, Latency p50/p95/p99, Error Rate); 

- ідентифікувати точку насичення (Saturation Point) та джерела деградації продуктивності (Bottlenecks); 

- емпірично вимірювати та порівнювати ефект від горизонтального масштабування (1 vs N instances) та шару кешування (Warm vs Cold Cache).

### **2.2. Конфігурація навантажувального контуру (Load Testing Environment)** 

1. Створити автоматизовані декларативні скрипти навантаження із застосуванням інструментів типу **k6, Locust або Gatling** . Зберегти їх у репозиторії проєкту (директорія /load-tests). Ручні запити з Postman/Swagger як засіб вимірювання заборонені. 

2. Фіксувати конфігурацію тестового середовища (Baseline Environment Specification): ресурси CPU/RAM, кількість backend instances, параметри Connection Pool, наявність та стан Redis-кешу. 

3. Забезпечити ізоляцію та мінімізувати ресурсову конкуренцію між Load Generator (генератором навантаження) та System Under Test (SUT). 

### **2.3. Моделювання профілю навантаження та Warm-up** 

1. Перед основним вимірюванням реалізувати фазу **Warm-up (розігріву)** для ініціалізації пулів з'єднань, DNS-кешу та JIT/Runtime оптимізацій. 

2. Налаштувати ступеневе збільшення навантаження (Staging Ramp-Up): наприклад, 10 → 25 → 50 → 100 → 200 Virtual Users (VUs) або прогресивне нарощування Target RPS.

### **2.5. Визначення Saturation Point та Первинного Bottleneck** 

1. Визначити **Точку насичення (Saturation Point)** — рівень навантаження, при якому Throughput перестає лінійно зростати, а затримки (Latency) та помилки (Error Rate) починають експоненціально підвищуватися. 

2. Сформулювати аналітичний висновок щодо виявленого первинного вузького місця (наприклад, DB Connection Pool Exhaustion, CPU Throttling у контейнері БД, Lock 

Contention при записі). 

### **2.6. Контрольні експерименти порівняльного аналізу** 

- **Scaling Impact Analysis:** Провести тестування для 1 backend instance проти 2+ instances у тотожних умовах. Оцінити коефіцієнт масштабованості (Scalability Efficiency Factor). 

- **Caching Impact Analysis:** Провести тестування для сценарію читання у режимах _Cache Disabled / Cold Cache_ проти _Cache Enabled / Warm Cache_ . Зняти вимірювання затримки та зниження навантаження на СУБД.

## **4. Порядок захисту та критерії оцінювання** 

### **Процедура захисту:** 

1. **Демонстрація запуску тесту:** Виконання скрипту навантаження у реальному часі зі ступеневим нарощуванням VUs. 

2. **Аналіз результатів:** Пояснення різниці між Median (p50) та Tail Latency (p99), доведення точки насичення системи на графіках. 

3. **Демонстрація порівняльних режимів:** Показ різниці продуктивності між scaled/non-scaled конфігураціями та cached/uncached станами. 

4. **Теоретичний захист:** Пояснення поняття Saturation Point, координаційної омани (Coordinated Omission), впливу Garbage Collection/JIT на перцентилі затримок. 

### **Критерії оцінювання:** 

- **Детермінованість тестування:** Використання професійних інструментів та 

відтворюваних скриптів. 

- **Глибина аналізу метрик:** Обґрунтування результатів на основі перцентилів (p95/p99), а не лише середнього значення. 

- **Аргументованість висновків:** Чітка ідентифікація точки деградації та первинного bottlenecks.
