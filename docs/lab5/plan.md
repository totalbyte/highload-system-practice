## Етап 2. Сценарії A / B / C (2.1, 2.3) — ✅

- **A — Read-Intensive (Учасник 2):** `GET /api/polls/{id}/results` по гарячих опитуваннях (лайв-дашборд) + `GET /api/polls/{id}`.
- **B — Write-Intensive (Учасник 2):** голосування й зміни голосу — транзакція, `FOR UPDATE`, рядкові блокування `vote_count`.
- **C — Complex Workflow (Учасник 1):** автор створює опитування → публікує → користувачі читають, голосують → результати → закриття.
- Спільне: логін у `setup()` (логін навмисно CPU-важкий і не міряється), токени на всі VU; **warm-up** перед вимірюванням;
  **ступеневий ramp-up** 10 → 25 → 50 → 100 → 200 VU з плато на кожному рівні; метрики окремо по кожному ступеню;
  підсумок у JSON для таблиць і графіків.

## Етап 4. Порівняння (2.6) — ✅

- **Scaling (Учасник 1):** 1 vs 2 vs 3 інстанси в тотожних умовах, коефіцієнт масштабованості `RPS(N) / (N × RPS(1))`.
- **Caching (Учасник 2):** сценарій A з кешем вимкненим / холодним проти увімкненого / теплого: latency і навантаження на
  PostgreSQL (запити до БД за секунду, CPU `postgres`).
