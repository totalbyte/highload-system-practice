## Problems & fixes
- `option httplog` in `defaults` + `no log` in `listen stats` gave the warning "log format ignored for proxy 'stats'",
  and `no option httplog` is not supported → moved `option httplog` to the frontend.
- A config reload took ~6.5 s: with `init-addr last,libc,none` the new worker resolves `backend-3` through libc, and a
  lookup of a non-existent name via Docker DNS takes ~6 s (`getent hosts backend-3` in the `lb` container: 8 s incl.
  `docker exec`). Switched to `init-addr none` → reload 0.37 s; servers still get their addresses from the runtime
  resolver immediately ("IP changed from '(none)'", "UP/READY").
- The first smoke-test run failed at login: right after `docker compose rm -sf backend-3`, HAProxy still had the node
  UP (TCP check, `inter × fall` ≈ 6 s), retried the connect 4 × 2 s on the same node and returned 503 after 8 s
  (`sC--`). Not a П1-1 defect — recorded in ADR 0031 / runbook as the gap closed by П1-3 (`/health` checks,
  `option redispatch`). The rerun on a stable pool passed.

- Five cold starts in a row with `backend-1..3` starting together (`--profile scale down -v && … up -d`, helper script in
  the session scratchpad, not committed): all three UP on `/stats;csv` after 18–19 s, `RestartCount` 0/0/0, one

  The `CREATE TABLE IF NOT EXISTS` race from ADR 0022 did not show up.
- Pool budget under load (Python `ThreadPoolExecutor`, 150 threads, `GET /api/polls?pageSize=50` through :8080, sampling
  `pg_stat_activity` meanwhile; scratchpad, not committed — Participant 2's `load.py` comes in П2-2): 15 s, 5224 × 200,
  1742 / 1741 / 1741 per instance, peak 90 backend connections (30 per container address), psql connects.
  With `DB_MAX_POOL_SIZE=22`: peak 66 = 22 × 3, all 200. Stack restored to pool 30 and two instances afterwards.
- Found: the app role `polling` is a superuser, so PostgreSQL's 3 reserved slots don't protect admin tools from the
  backends; the budget is now *instances × pool ≤ 90* (10 spare slots).
- [ADR 0032](../decisions/0032-connection-budget-for-scale-out.md): 4+ instances → `DB_MAX_POOL_SIZE = floor(90 / N)`
  via `.env`, `max_connections` stays 100 (more connections don't make one PostgreSQL faster; waiting in the pool is the
  measurable bottleneck). ADR 0018 marked amended; runbook budget text and quirk rows; `.env.example` comment.
