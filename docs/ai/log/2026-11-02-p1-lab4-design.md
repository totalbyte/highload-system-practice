## Problems & fixes
- `cache-demo.py` crashed when Redis was stopped: Docker's published port still accepts the TCP connection and closes
  it with an empty reply — treated as "unavailable".
- ADR 0027 said Redis "comes back empty" after a restart (no volume). Wrong for `docker compose stop` / `start`: the
  default `save` points write `dump.rdb` into the container filesystem on shutdown and it is loaded on start
  (`keys loaded: 24`). With fail-fast this would have served invalidation-missed entries after a short outage → Redis
  now runs with `--save ""`.
- Shell-quoting pitfall on Participant 1's machine: a double backslash in an inline Python edit reached Python as a single one even inside a quoted heredoc, so a Python edit with `"\\n"`
  wrote real newlines into `redis-outage-check.py` (SyntaxError). Fixed with `chr(92)`; later edits go through a script
  file written with the Write tool.
- The working tree uses CRLF (`core.autocrlf=true`); text appended via a shell heredoc was LF. Normalized README and
  status to CRLF in the working tree (the repository keeps LF via `.gitattributes`).
- The first version of the race check (one vote per round) found nothing on **both** builds (0 of 200): with a
  single vote the cache is hot during the vote and readers only miss after the `DEL`, i.e. already post-commit. The
  race needs a second invalidation while a reader that missed after the first is between its DB read and its `SET`
  → rounds of 8 simultaneous votes for one option (commits queue on the `vote_count` row lock).
